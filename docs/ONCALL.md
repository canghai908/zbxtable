# 值班排班（第一期）

## 使用

管理员进入“告警管理 → 值班排班”。创建排班，选择 IANA 时区（默认 Asia/Shanghai）、轮换起点、成员顺序、覆盖星期和时段。固定模式所有成员同时值班；按天/按周模式每班选择一人，按成员顺序循环。交接使用轮换起点在排班时区中的钟点，按当地日历天/周计算。

覆盖时间相同表示全天，结束早于开始表示跨午夜；午夜后的覆盖归属上一天的星期。覆盖和临时代班时间为左闭右开 `[start,end)`。临时代班覆盖正常轮换及正常空班，但不覆盖尚未开始或已禁用的排班；重叠代班拒绝保存，代班结束后恢复原轮换顺序。

在“告警分发”中选择一份或多份值班排班，可与原固定用户/用户组组合。最终按用户和渠道去重。旧规则不需要修改；旧客户端更新时省略 schedule_ids 不会清空已有排班，显式空数组则解除关联。

## 今日当班与我的值班

列表显示每份排班当前人员，可点击“今日 N 个时段”查看排班时区的完整今日班次。“我的值班”按登录账号筛选轮班成员、未来 31 个当地日内的临时代班及备用用户/用户组，再分页；不能通过请求参数冒用其他账号。当前/下一班查询未来 31 个当地日，持续至查询边界时明确标注查询期，备用身份不代表已实际接班。

编辑器将首次日期与交接钟点分开，均按所选排班时区解释；切换时区后以新时区解释当前输入。旧排班未调整日期、时刻、时区时保留原始起点字符串及精度。新输入遇到夏令时不存在或重复的钟点会提示调整，避免静默改变交接时间。“全天值班”映射原有相等的覆盖端点，自定义覆盖时段仍受支持。

按完整自然日轮班时，点击“零点交接”选择 `00:00:00`，每班覆盖 `[当日 00:00, 次日 00:00)`。交接时间代表下一人接班的时刻，`23:59:59` 会在午夜前一秒换人，不能代替零点。时间面板支持始终滚动或直接输入，摘要保留秒数。已有 `23:59:59` 配置不会静默重写；编辑时会提示，可点击“零点交接”并保存后更正。

保存前可查看轮班成员及备用用户的启用状态和邮件、企业微信、群机器人地址是否配置。检查仅返回布尔状态，不返回邮箱地址、密码或机器人密钥；不会验证远端投递，也不展开备用用户组成员。缺少地址不阻止保存，实际分发仍按渠道检查并使用兜底。

## 兜底与通知

按通知生成时间解析当班人员。对每个渠道分别检查用户是否启用、渠道地址是否非空；本渠道没有可用值班人时，尝试排班备用用户及备用用户组。禁用排班停止正常轮换，关联规则仍尝试兜底；无可用兜底时显示“无可用接收人”，不记为发送成功。渠道是否已正确配置和远端实际投递结果仍由现有发送模块负责。

分发规则生效时间继续使用原来的服务器本地时区；排班覆盖时间使用各排班自己的时区。屏蔽规则继续在最终渠道入队前生效。

具有有效 Zabbix eventid 的排班通知会按 `zid + eventid + channel` 保存首次实际接收人快照。交接或排班变更后，同事件重试优先使用快照；队列中的 ToUsers 已固定，消费时不重新选择值班人。无法关联到同一 eventid 的恢复事件不会猜测关联，也不实现确认、升级或定时重发。快照不存邮箱、Webhook Key 等凭据。

## 预览

排班详情默认预览“排班人员”：显示原始轮班及临时代班，不按渠道地址筛掉成员。按天轮班每个时刻一人，多名成员按配置顺序逐天循环。切换为“邮件接收人 / 企业微信接收人 / 群机器人接收人”时，才按渠道可达性和兜底配置预览实际通知对象；若其他成员缺少渠道地址，多个日期可能显示同一兜底人员，这不代表轮班配置丢失。

明细列表可选择未来 7/14/31 天，月日历显示完整月份。预览包含代班/轮班/兜底/空班原因。预览边界包含跨午夜、交接、临时代班和 DST 时区变更，不会遗漏短代班。

分发编辑页“测试分发接收人”模拟当前这一条规则，检查实例范围、条件、生效时间、排班接收人、兜底与已有屏蔽规则。它不会枚举其他规则或代表整个默认回退链，也不读取某个已有事件的通知快照。预览不写入通知队列或快照。

## 存储与权限

启动时 GORM 增量迁移：新增 oncall_schedule、oncall_override、oncall_audit、oncall_dispatch_snapshot 表（实际表名加 zbxtable_ 前缀），rule 表新增可空 schedule_ids 文本 JSON 列。启用的普通账号和管理员均可查看名单、详情、代班与预览；新增、修改、删除、代班维护、审计和引用排班的规则写操作仅管理员可用。权限由后端校验，匿名与禁用账号不可访问。被规则引用的排班禁止删除；引用检查/写入及删除使用事务与一致的排班行锁。配置和代班变更均记录操作人与审计详情。

需同步发布前后端并重启后端完成迁移，菜单检查会自动补充“值班排班”，并幂等更新已有菜单为 admin,user；普通账号重新登录可刷新菜单权限。未增加依赖。上线前使用正常数据库备份流程；旧版本不能处理排班选择和新增通知状态。

- 前端 68 项测试、lint、生产构建；隔离模拟接口检查实际页面在 1366×768、390×844 的布局。

### 三人按天轮班预览回归

已验证通过API创建两人成员排班、编辑为三人后重新读取保留完整顺序；连续七天原始轮班为A/B/C/A/B/C/A。仅A有邮箱且A为兜底时，邮件渠道预览连续七天均为A，B/C当天来源为fallback。默认前端使用不指定渠道的预览，避免将原始排班与通知对象混淆；实际分发可达性和兜底逻辑保持。
