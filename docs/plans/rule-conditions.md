# 条件分组实施计划

1. 先补充旧规则 AND、默认空条件与分发回退的回归覆盖。
2. 引入版本化 AND/OR 条件树，旧数组读取为 AND；校验字段、操作符、正则、深度和数量。
3. 实际分发、屏蔽和条件测试复用同一求值器，测试返回逐项命中解释，无通知副作用。
4. 两页面复用条件编辑、摘要和测试组件，保存时禁止无效条件。
5. 运行 Go 测试、构建、vet、前端 lint/build 与 CI 同款 gofmt 检查。

范围：本期只测试条件表达式；实例、生效时间、渠道及发送模拟不纳入此接口。旧空默认规则仍匹配；普通空条件仍不匹配。条件最多三级分组、50 个叶子，不新增依赖。已有设备图表修改保留。

## 兼容与发布

- 原 conditions 数组自动按 AND 求值；兼容 `=`、`==`、`!=`、`like`、`=~`。
- 新条件使用 version=2 对象，仍存在原 text 列，不新增表或依赖。
- 普通规则和屏蔽规则保存时禁止空条件；默认规则仍允许空条件。
- 无效字段、操作符、正则和分组拒绝保存，已有无效规则求值为不匹配。
- 前后端应一同发布；新版条件写入后，旧前端/后端无法解释条件树。降级前需恢复旧条件备份。

## 操作与验收

在分发或屏蔽规则编辑页面，选择“满足全部 AND / 满足任意 OR”，通过“添加条件组”组合括号关系。列表和编辑器预览显示相同树结构。展开“测试条件匹配”，输入主机、主机组、监控项、Key、告警内容、等级样例，查看每个条件的实际值与命中结果。修改条件或样例后，上次结果失效。

测试不会发送消息，仅计算条件。实例、生效时间、渠道、启用状态仍由原分发和屏蔽流程判断，不纳入本期测试接口。主机组保持旧数据的字符串语义；等级也保持精确字符串匹配，不添加未经现有告警数据验证的成员或大小比较。

后端验证：go test ./...、go build ./...、go vet ./...；格式使用 CI 的 git ls-files '*.go' | xargs gofmt -l，并单独检查新增 Go 文件。
