# 排班第一期实施计划

范围：固定/按日/按周轮班、时区与覆盖时间、临时代班、按渠道空班兜底、分发规则选择排班、排班预览与分发模拟。兼容旧规则的用户/用户组发送；不实现确认升级或延时任务。

实现：新增独立排班/代班/审计表；规则增加可空 schedule_ids；收件人解析复用在预览与实际分发中。按通知生成时间选择值班人，缺少渠道地址/用户禁用时走兜底；多人多规则按用户和渠道去重。无可用兜底显式记录，不能记为成功。新增只含排班的通知快照，按实例+事件+渠道保留收件人解释，重试沿用快照。

并行边界：后端排班模型及CRUD/预览；前端排班管理与规则选择；主任务负责路由、迁移、分发接入及测试整合。既有本地改动保留。

验证：轮班边界/跨午夜/DST/代班覆盖冲突/空班与渠道兜底、规则兼容和去重、鉴权及预览无发送副作用；Go全量测试/build/vet、竞态检查、gofmt；前端测试/lint/build和紧凑布局检查。

实施完成：接入独立排班/代班/审计模型和菜单、按渠道收件人解析、快照优先重试及分发模拟。增加事务锁保护规则引用；修正实例ID模糊匹配，避免实例1意外使用实例12的规则。处理DST重复小时/缺失小时预览边界并补充回归测试。

完整使用与验证说明见 ../ONCALL.md。隔离 PostgreSQL 已验证旧规则迁移、实际GenAlert入队与API；通知消费者未启动，不产生外部消息。MySQL仅共用GORM代码与构建检查，未做真实MySQL运行验证。
